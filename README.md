# НЕ КУРЮ И НЕ БУХАЮ — Flutter starter v0.3

Android-first исходный проект. Общий Dart-код можно использовать и для будущей iOS-версии.

## В каркасе реализовано

- Тёмная тема и нижняя навигация: Главная / Прогресс / Деньги / Награды / Профиль.
- Независимый учёт курения и алкоголя.
- Локальное хранение параметров, периодов и событий через SharedPreferences.
- Офлайн-работа без регистрации.
- Раздельные серии, календарь и фиксация срывов без удаления прошлых периодов.
- Расчётная экономия отдельно от фактически отложенных денег.
- Цель накопления, базовые достижения и кнопка поддержки.
- Код разбит на `core` и `features`; слой `HabitRepository` отделяет интерфейс экранов от способа хранения и оставляет место для облачной реализации.

## Честно о готовности

ZIP содержит исходный Flutter-каркас, но не содержит собранный APK. В среде подготовки архива Flutter SDK и Android SDK отсутствуют, поэтому компиляция, `flutter analyze`, `flutter test` и APK-сборка фактически не запускались. Это нужно выполнить на компьютере с Flutter и Android SDK до установки и тем более до публикации.

## Сборка APK на Windows

1. Установить Flutter SDK по официальной инструкции: https://docs.flutter.dev/get-started/install
2. Установить Android Studio. В SDK Manager установить Android SDK Platform, Build-Tools и Platform-Tools.
3. Распаковать архив в папку, например `C:\Projects\ne_kuryu_ne_buhayu`.
4. Открыть PowerShell в этой папке.
5. Создать платформенные каталоги Android и iOS:

   ```powershell
   flutter create --platforms=android,ios .
   ```

   Команда генерирует стандартные платформенные файлы. Исходники приложения находятся в `lib`; не заменяйте эту папку пустым шаблоном.

6. Проверить инструменты и принять Android-лицензии:

   ```powershell
   flutter doctor
   flutter doctor --android-licenses
   ```

7. Загрузить зависимости и проверить проект:

   ```powershell
   flutter pub get
   flutter analyze
   flutter test
   ```

8. Подключить Android-телефон по USB, включить «Для разработчиков» и «Отладку по USB», подтвердить разрешение на телефоне. Проверить устройство и запустить:

   ```powershell
   flutter devices
   flutter run
   ```

9. Собрать APK:

   ```powershell
   flutter build apk --release
   ```

10. После успешной сборки файл будет находиться здесь:

   ```text
   build\app\outputs\flutter-apk\app-release.apk
   ```

   Скопируйте его на телефон и откройте для установки. При запросе Android разрешите установку из выбранного файлового менеджера.

## Вариант без Windows: сборка APK в GitHub Actions

В архив добавлен workflow `.github/workflows/android-apk.yml`. После загрузки проекта в GitHub он может собрать APK на облачном runner:

1. Создать пустой GitHub-репозиторий.
2. Загрузить в него содержимое распакованного архива (включая скрытую папку `.github`).
3. Открыть вкладку **Actions** и выбрать workflow **Build Android APK**. Если он не стартовал автоматически после загрузки файлов, нажать **Run workflow**.
4. Дождаться зелёного статуса завершения сборки.
5. Открыть завершённый запуск, найти блок **Artifacts** и скачать `ne-kuryu-ne-buhayu-android-apk`.
6. Распаковать скачанный архив, перенести `app-release.apk` на телефон и установить.

Если workflow завершится ошибкой на `flutter analyze`, `flutter test` или сборке, APK не будет опубликован как успешный артефакт. Текст ошибки находится внутри запуска Actions; сначала нужно исправить указанную проблему. Этот облачный путь не требует установленной Windows на твоём компьютере, но требует загрузить исходники в GitHub.

## iOS и облако в дальнейшем

Для iOS понадобится Mac с Xcode и настройка подписи Apple; затем можно будет собирать IPA командой `flutter build ipa`. Бизнес-логика написана на Dart и не использует Android-only API.

Сейчас подключён `LocalHabitRepository`, реализующий интерфейс `HabitRepository`. Для облачной синхронизации можно добавить вторую реализацию и механизм синхронизации поверх локальных данных. Это позволит сохранить офлайн-режим и не отправлять данные без согласия пользователя.

## Формулы MVP

- Курение: `сигарет в день / сигарет в пачке × цена пачки × суммарные дни отказа`.
- Алкоголь: `средние недельные расходы / 7 × суммарные дни отказа`.
- Завершённые периоды до срыва остаются в истории и учитываются в расчётной экономии.
- «Фактически отложено» вводится отдельно и не подменяется расчётной экономией.

Перед коммерческим релизом потребуются дополнительные тесты, тестирование на реальных устройствах, политика конфиденциальности, экспорт/резервное копирование, уведомления и юридическая проверка медицинских предупреждений.
